# SAVED GEMATRIA LIBRARY — PREMIUM PERSONAL LIBRARY REDESIGN

Redesign the existing **שמורים** page of the Gematria application based closely on the attached visual mockup.

## CRITICAL PRINCIPLE

This is a **UI/UX enhancement of the EXISTING saved library**.

It is NOT:

* a database redesign
* a new saved-entry system
* a new matching engine
* an authentication project
* a new application
* an excuse to rewrite working logic

The attached mockup is the VISUAL TARGET.

The current application/database is the FUNCTIONAL SOURCE OF TRUTH.

Preserve all existing saved data and all existing save/search/delete/open behavior unless this specification explicitly improves the presentation.

---

# 1. CURRENT PROBLEM

The current שמורים page works, but every saved entry occupies a very wide horizontal row while only using a small part of that width.

This creates:

* too much dead space
* weak information hierarchy
* slow visual scanning
* a database/admin-list feeling

The new page should feel like:

**הספרייה האישית של המשתמש**

A personal Gematria library.

It should feel:

* refined
* compact
* warm
* traditional
* modern
* highly readable
* effortless to scan

Do NOT turn it into a SaaS dashboard.

---

# 2. PRESERVE THE EXISTING DESIGN LANGUAGE

Use the visual system already established throughout the application:

* warm cream/off-white background
* deep navy Hebrew typography
* restrained gold accent
* thin warm borders
* very soft shadows
* rounded corners
* RTL-first layout
* understated traditional character

Do NOT introduce:

* gradients
* dark panels
* bright colors
* glassmorphism
* large illustrations
* excessive icons
* heavy shadows
* generic admin-table styling

---

# 3. PAGE HEADER

Keep:

**שמורים**

Subtitle:

**הספרייה האישית שלך**

The heading should remain visually strong but not oversized.

Below it, keep the search field as the main interaction.

# 4. SMART SEARCH BAR

Keep one elegant full-width search field.

Placeholder:

**חפש לפי טקסט, מספר גימטריה או ראשי תיבות...**

Search should continue supporting the existing functionality and should be enhanced where safe to support:

* original Hebrew text
* normalized Hebrew text
* full gematria number
* ראשי תיבות text
* ראשי תיבות gematria

Examples:

Typing:

`יעקב`

→ finds saved text containing יעקב.

Typing:

`251`

→ finds entries whose relevant full gematria equals 251.

Typing:

`יא`

→ may find entries whose ראשי תיבות equals יא if already available in the search model.

Do not create a complex search language in this task.

Keep it fast and intuitive.

---

# 5. LIBRARY TOOLBAR

Directly below the search field, add a refined compact toolbar.

It should contain:

### Library summary

Show:

**X שמורים**

and, if safely derivable from currently loaded/database data:

**Y ערכים שונים**

and:

**Z ערכים משותפים**

Where:

* ערכים שונים = number of distinct full-gematria values
* ערכים משותפים = gematria values represented by more than one saved entry

Example:

**14 שמורים · 12 ערכים שונים · 2 ערכים משותפים**

Do not make these giant KPI cards.

This should be a subtle inline summary.

# 6. VIEW SWITCHER

Add a small elegant view selector:

* card/grid view
* list view

Use restrained icons from the existing icon library.

Default desktop view:

**grid/cards**

Mobile may automatically use one column.

Persist the view preference only if the application already has an appropriate non-destructive UI preference mechanism.

# 7. SORT CONTROL

* ישנים

**אחרונים**

# 8. GROUP-BY-GEMATRIA CONTROL

Add a useful library-specific toggle:

**קבץ לפי גימטריה**

This is an important Gematria feature.

It should NOT be active by default.

When enabled, entries sharing the same FULL GEMATRIA should be visually grouped together.

Example:

### 811 · תתיא

**2 ערכים שמורים**

Then show the two saved entries inside that group.

This makes numerical relationships in the user's own library visible immediately.

On desktop, replace the current giant full-width rows with a **two-column responsive card grid**.

Aim for a comfortable content width similar to the attached mockup.

Each card should use space efficiently.

Do NOT make the cards tiny.

Do NOT create three/four narrow columns.

Two columns is the preferred desktop balance.
