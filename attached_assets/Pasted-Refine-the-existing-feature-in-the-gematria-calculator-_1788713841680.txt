Refine the existing מילוי feature in the gematria calculator.

IMPORTANT:
This is a refinement of the current implementation.

==================================================
GOAL
==================================================

The current מילוי area is too complicated and visually noisy.

We want a cleaner and more intuitive structure:

1. In the MAIN מילוי area, show only the PRIMARY / MOST COMMON מילוי.
2. Under that, show the OTHER 3 מילוי options in a simpler secondary area.
3. Regular "שמור" should save only the DEFAULT / BASIC מילוי.
4. Add a second button:
   "שמור כל האופנים"
   which saves all available מילוי variants for the current input.
5. The entire experience must stay neat, modern, and simple.

==================================================
DESIRED UX LOGIC
==================================================

### A. Primary מילוי presentation

When the user opens מילוי, the first thing they should see is only the main / standard / most common מילוי.

This main area should contain:

- כותרת: "מילוי"
- a small subtitle if needed, subtle only
- "שם האות במילואה" / expanded text
- "גימטריית המילוי המלא"
- "מילוי בלבד"

This primary display should represent the **default / standard מילוי only**.

This is the version the user sees first.
This is also the version saved when the user clicks the regular save button.

### B. Secondary מילוי options

Below the main primary מילוי result, show the other 3 available מילוי forms.

These should be shown in a much lighter and simpler way than now.

Do NOT make them feel like the main result.
Do NOT clutter the top area with all options equally.

They should appear as a secondary section such as:

"אופנים נוספים"
or
"אפשרויות נוספות"

Each option should be shown clearly and compactly.

For each secondary option, show:
- the variant label
- the expanded text
- the total מילוי gematria
- the מילוי בלבד gematria

But keep these compact and visually subordinate.

==================================================
SAVE LOGIC
==================================================

We need two distinct save actions.

### 1. Regular save button

Keep the existing standard save button:
"שמור"

New logic:
When the user clicks "שמור", save ONLY the PRIMARY / DEFAULT / BASIC מילוי.

Meaning:
- save the current input as normal
- save the standard מילוי version only
- do NOT automatically save the other מילוי variants

This should be the default behavior.

### 2. New save-all button

Add a second clearly labeled button:
"שמור כל האופנים"

When clicked:
- save the current input
- save all available מילוי variants for that input
- this should include the primary מילוי and the 3 other variants

This button must be visually secondary to the main "שמור", but still easy to find.

Suggested hierarchy:
- primary button: "שמור"
- secondary button / outlined button: "שמור כל האופנים"

Do not make the layout feel crowded.

==================================================
VISUAL HIERARCHY
==================================================

The problem now is that all variants are competing visually.

We want this hierarchy:

1. MAIN / PRIMARY מילוי result
   - large
   - calm
   - elegant
   - easiest to read

2. Secondary options area
   - compact
   - quieter
   - neatly stacked or in compact cards/rows
   - clearly "other options", not equal to the primary one

3. Save actions
   - "שמור" close to the main result
   - "שמור כל האופנים" nearby, but less dominant

The user should immediately understand:
- this is the main מילוי
- here are other valid options
- I can save just the main one
- or save all of them
