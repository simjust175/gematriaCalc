# MASTER IMPLEMENTATION — מילות יסוד

We are replacing the current generic כפולות feature with a new, much more deliberate feature called:

מילות יסוד

This is a production application with real client data and the client is actively using it.

The implementation must be:
- additive
- production-safe
- visually refined
- extremely simple for the end user
- consistent across Calculator, תנ״ך, and the dedicated management section

Do NOT perform unrelated refactors.

======================================================================
1. PRODUCT DEFINITION
======================================================================

מילות יסוד is a CURATED list of specific Hebrew words or phrases that the client explicitly chooses.

Examples could include:

י־ה־ו־ה
אהיה
אדני
שמע ישראל

The application should compare the CURRENT COMPLETE FULL GEMATRIA against ONLY these explicitly created מילות יסוד.

Do NOT automatically use:

- ordinary saved entries
- words inside saved phrases
- saved word breakdowns
- ראשי תיבות
- גימטריית ר״ת
- מילוי
- Tanach words
- random saved phrases

Only explicit מילות יסוד participate.

This is the central rule.

======================================================================
2. REPLACE THE OLD כפולות FEATURE
======================================================================

The current generic כפולות feature searches random values from saved material.

The client does NOT want this anymore.

Replace the user-facing כפולות feature with:

מילות יסוד

The old generic results must no longer appear in the calculator.

IMPORTANT:

Do NOT delete existing SavedEntry / SavedWord records.

Do NOT destructively remove existing production data merely because it is no longer used by כפולות.

If old derived data/indexes are harmless and used elsewhere, leave them intact.

We are removing the OLD DISCOVERY BEHAVIOR, not deleting client history.

======================================================================

Every מילת יסוד is treated as ONE complete text unit.

Example:

שמע ישראל

It must NOT separately use:

שמע
ישראל

This rule applies everywhere:

- manual creation
- calculator save-as
- Tanach save-as
- matching

Never automatically split a מילת יסוד into component words for matching.

======================================================================
4. CURRENT VALUE TO CHECK
======================================================================

מילות יסוד compares against ONLY:

the current complete גימטריה מלאה of the calculator input.

Do NOT compare against:

- current individual words
- current selected word
- current ראשי תיבות
- current גימטריית ר״ת
- current מילוי
- word breakdown
- Tanach subwords

The relationship is strictly:

CURRENT COMPLETE FULL GEMATRIA

versus

COMPLETE GEMATRIA OF EACH מילת יסוד

======================================================================
5. EXACT WHOLE-NUMBER RULE
======================================================================

For:

currentValue = C
milatYesodValue = B

A result exists only when:

B > 0

and:

C % B === 0

Then:

times = C / B

Only exact whole-number division is valid.

Example:

י־ה־ו־ה = 26

Current gematria = 260

260 / 26 = 10

VALID.

Current gematria = 65

65 / 26 = 2.5

INVALID.

Do NOT show:

- halves
- decimals
- fractions
- percentages
- approximate matches
- rounded matches
- near matches

Exact division only.

Use:

for 1.

Use:

פעמים

for 2+.

THAT IS ALL.

Do NOT show in the normal result row:

The simplicity is intentional.
