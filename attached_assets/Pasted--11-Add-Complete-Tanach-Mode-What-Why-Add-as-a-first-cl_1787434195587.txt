#11 — Add Complete Tanach Mode
What & Why

Add תנ״ך as a first-class section of the existing Hebrew Gematria application.

Users should be able to browse the complete Hebrew Tanach, select any ספר / פרק / פסוק, move an accessible cursor through the canonical Hebrew text, and watch the gematria accumulate instantly as the cursor moves through additional letters.

The currently selected Tanach range should behave like live calculator input:

full gematria
Hebrew-number representation
ראשי תיבות
gematria of ראשי תיבות
word breakdown
letter breakdown
existing saved-match detection
ability to save the selected range

Do this WITHOUT changing or rebuilding the existing מחשבון or שמורים functionality.

CRITICAL — QERE / KETIV

UXLC distinguishes normal text and קרי/כתיב variants.

Do NOT accidentally concatenate both alternatives and count them as though they are sequential words.

Preserve:

ordinary word text
כתיב
קרי

when present.

For this initial Tanach reader, use a single consistent resolved-reading policy for:

displayed reading text
cursor positions
gematria
word breakdown
ראשי תיבות
search
saving
matching

Prefer the normal קרי / reading form when a qere exists, while preserving the כתיב as structured metadata for possible future support.

Most importantly:

Never count both קרי and כתיב simultaneously.

Add tests using actual UXLC qere/ketiv examples proving that alternative readings are never double-counted.

5. GEMATRIA CURSOR — CORE FEATURE

This is the central new feature.

The user must be able to move a cursor through the actual Hebrew LETTERS of the verse.

As the cursor moves forward, continuously calculate the gematria from the current START POSITION through the CURRENT LETTER.

Spaces and formatting characters must not contribute.

Example using בראשית א׳:א:

ב

Gematria:

2

913

Move through:

בראשית ברא

1116

Continue to the end:

2701

Everything must update immediately.

Preserve the original display string separately from the normalized/calculation representation.

Do not damage visual Hebrew merely to simplify calculation.

Do NOT implement complicated document-editor selection behavior.
