# TANACH DISCOVERY — CLEAN UI + FIX MAQAF/HYPHEN WORD TOKENIZATION

The new Tanach ראשי תיבות / סופי תיבות functionality works conceptually, but two things need correction:

1. The Tanach search controls now look cluttered/messy.
2. Words joined by a Hebrew maqaf/hyphen are incorrectly being treated as one word.

This task must fix BOTH issues.

Do not make unrelated changes.

==================================================
PART A — CRITICAL TOKENIZATION FIX
==================================================

For ALL Tanach logic that depends on WORDS / WORD COUNT:

A Hebrew maqaf or hyphen between Hebrew words MUST count as a WORD SEPARATOR.

Example:

בית־אל

must tokenize as:

בית
אל

WORD COUNT = 2

NOT:

בית־אל
WORD COUNT = 1

This is the required product behavior even if the source Tanach text visually uses a maqaf.

==================================================
1. SEPARATORS TO SUPPORT
==================================================

Treat these as word separators when they occur between Hebrew text:

Hebrew maqaf:
־
U+05BE

regular hyphen:
-

non-breaking hyphen:
-

en dash if encountered:
–

Do this safely and consistently.

Do NOT require visible spaces around them.

Examples:

בית־אל
בית-אל
בית-אל

all become two logical words:

בית
אל

==================================================
2. PRESERVE ORIGINAL DISPLAY TEXT
==================================================

IMPORTANT:

Only the INTERNAL TOKENIZATION changes.

Do NOT rewrite the Tanach display text.

If the verse originally says:

בית־אל

the result card should still DISPLAY:

בית־אל

with its original maqaf.

Internally, however, search logic must understand it as two words.

==================================================
3. APPLY THIS CONSISTENTLY
==================================================

Use the SAME tokenizer for:

- calculator input word count
- ראשי תיבות derivation
- סופי תיבות derivation
- Tanach candidate word windows
- whole-word / multi-word Tanach classification where word boundaries matter

Do not have one tokenizer for input and another for Tanach.

Centralize/reuse the existing Hebrew tokenizer if possible.

==================================================

אל
הגדול

==================================================
6. GEMATRIA MUST NOT CHANGE
==================================================

Do NOT change the normal numeric gematria result.

Maqaf/hyphen remains ignored for gematria itself.

This task only changes WORD BOUNDARY interpretation.

==================================================
7. TEST THE TANACH CORPUS
==================================================

Add regression tests using actual-style Tanach strings containing maqaf.

Verify:

- א־ב = 2 words
- בית־אל = 2 words
- multi-maqaf phrase creates correct number of logical words
- ראשי תיבות uses each logical word
- סופי תיבות uses each logical word
- search-window size uses logical word count
- result display preserves the original maqaf

PART B — CLEAN UP THE TANACH SEARCH UI
==================================================

The current UI is visually too busy.

At the moment we have:

- section title
- huge result count
- גימטריה / ראשי תיבות / סופי תיבות control
- Tanach scope selector
- פרשת השבוע button
- another row of result-type filters

All of these appear as separate controls competing for attention.

Simplify this significantly.

==================================================
8. SEARCH METHOD CONTROL
==================================================

Keep these three methods:

גימטריה
ראשי תיבות
סופי תיבות

But make them ONE small, clean segmented control.

Do not make it look like three large buttons.

Preferred style:

גימטריה | ראשי תיבות | סופי תיבות

- compact
- single shared outer container
- subtle selected state using existing gold
- no heavy shadow
- no large padding

[compact method selector]
