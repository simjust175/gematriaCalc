# TANACH ראשי תיבות / סופי תיבות — CORRECT SEARCH LOGIC + CLEAN UI

The current implementation misunderstood the intended ראשי תיבות / סופי תיבות Tanach search.

We need to correct the search model.

IMPORTANT:
The Hebrew letters ENTERED IN THE CALCULATOR are themselves the pattern.

Do NOT derive a new ראשי תיבות string from the entered words for this Tanach feature.

==================================================
1. CORRECT ראשי תיבות LOGIC
==================================================

Example current calculator input:

שבמ

Normalize it to the Hebrew letter sequence:

שבמ

This contains 3 Hebrew letters.

Therefore search Tanach for contiguous sequences of EXACTLY 3 logical words where:

word 1 starts with ש
word 2 starts with ב
word 3 starts with מ

Example valid result:

שמע בני מוסר

because:

שמע → starts with ש
בני → starts with ב
מוסר → starts with מ

Therefore:

שמע בני מוסר

is a valid ראשי תיבות match for:

שבמ

==================================================
2. EVERY ENTERED LETTER = ONE WORD SLOT
==================================================

The number of normalized Hebrew letters in the current calculator input determines the number of words in the Tanach candidate.

Examples:

אב
→ search 2 consecutive words
→ first word begins א
→ second word begins ב

שבמ
→ search 3 consecutive words
→ initials must be ש ב מ

אבגד
→ search 4 consecutive words
→ initials must be א ב ג ד

This is the core rule.

==================================================
3. INPUT NORMALIZATION
==================================================

For this search mode, extract the actual Hebrew LETTERS from the current calculator text.

Ignore:

- spaces
- punctuation
- niqqud
- cantillation
- quotation marks
- geresh/gershayim
- maqaf/hyphen
- other non-Hebrew characters

Example:

שב״מ

should produce:

שבמ

Example:

ש ב מ

should also produce:

שבמ

Do NOT calculate gematria for determining this pattern.

==================================================
4. DO NOT USE INPUT WORD COUNT
==================================================

This is important.

The previous implementation treated input words as the basis of ראשי תיבות matching.

That is NOT what we want.

For Tanach ראשי תיבות search:

PATTERN LENGTH
=
number of Hebrew letters entered

NOT:

number of words entered.

Example:

שבמ

is one typed word but produces a THREE-WORD Tanach search.

==================================================
5. סופי תיבות LOGIC
==================================================

Use the exact same pattern concept for סופי תיבות.

Input:

שבמ

Search Tanach for exactly 3 consecutive logical words where:

word 1 ENDS with ש
word 2 ENDS with ב
word 3 ENDS with מ

The letters remain in exact order.

No reordering.
No skipping words.
No approximate matching.

==================================================
6. FINAL LETTER NORMALIZATION
==================================================

For סופי תיבות matching, normalize final forms consistently:

ך = כ
ם = מ
ן = נ
ף = פ
ץ = צ

Example:

pattern:
מ

may match a word ending:

ם

because internally both represent מ.

Preserve original Tanach spelling for display.

==================================================
7. COMPLETE WORDS ONLY
==================================================

Both ראשי תיבות and סופי תיבות searches must use complete logical Tanach words.

Never use:

- partial words
- substrings
- middle letters
- skipped words
- non-contiguous words

Each pattern letter corresponds to exactly one complete word.

==================================================
8. MAQAF / HYPHEN WORD BOUNDARIES
==================================================

Preserve the recently approved rule:

בית־אל

must count internally as TWO logical words:

בית
אל

although it must continue to DISPLAY as:

בית־אל

The canonical Hebrew tokenizer must treat maqaf/hyphen as a word boundary for this search as well.

Therefore a result may span logical words separated visually by maqaf.

==================================================
9. SAME VERSE ONLY
==================================================

A result must remain within one verse.

Never continue a ראשי תיבות or סופי תיבות sequence into the next verse.

==================================================
10. EXACT ORDER
==================================================

Input:

שבמ

valid initials:

ש → ב → מ

Not:

ש → מ → ב

Not:

ב → ש → מ

Not any permutation.
